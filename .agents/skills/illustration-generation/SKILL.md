Use this skill to generate and refine the final illustrations of a storybook.

This is the **illustrator's job**: given the illustration specs (scene prompts from the prompt-design skill) and the visual references (concept artworks from the artwork-generation skill), produce the actual illustrations for every scene and illustrated book part.

This skill defines the execution work of illustration:

- assembling render prompts from scene prompts, image anchors, style, and constraints,
- generating illustration images for scenes and book parts,
- reviewing generated illustrations for quality and faithfulness,
- iterating on specific scenes through prompt engineering when needed,
- checking that the final result is satisfactory alongside the user.

This skill does **not** handle:

- scene breakdown or scene texts (use the segment-story skill),
- concept identification or anchor definition (use the concept-definition skill),
- style definition or concept artwork generation (use the artwork-generation skill),
- deciding what to illustrate in each scene (use the prompt-design skill).

Use the repository's authoritative schema, storage rules, prompt-building code, and validators for artifact structure and compliance.

Workflow
--------

1. Read the storybook, its concepts, artworks, style, constraints, and scene prompts.
2. Inspect any existing generated illustrations.
3. Determine which illustrations should be generated, regenerated, or kept.
4. For each target (scene or illustrated book part):
   a. Assemble the render prompt using the prompt-building pipeline (resolve anchors, apply style and constraints).
   b. Collect the relevant concept artworks (image anchors) for concepts present in the scene.
   c. Generate the illustration using the assembled prompt and image references.
   d. Record the generated image path in the storybook artifact.
5. After generating all illustrations, review them for:
   * visual quality and clarity,
   * faithfulness to the scene prompts,
   * consistency of recurring concepts across scenes,
   * coherence with the global visual style.
6. For illustrations that do not meet quality expectations:
   a. Diagnose the issue (prompt clarity, concept representation, composition, etc.).
   b. Adjust the render prompt through prompt engineering (e.g., rephrasing, emphasis, negative constraints).
   c. Regenerate the illustration.
   d. Repeat until satisfactory or escalate to the user for guidance.
7. Persist the final storybook state with all illustration paths recorded.
8. Run the relevant repository validators and consistency checks.
9. Repair weak or invalid illustration state before declaring the work complete.

Prompt Engineering
------------------

When an illustration does not meet expectations, the illustrator should:

* identify what went wrong (wrong concept appearance, poor composition, style drift, etc.),
* adjust the prompt to address the specific issue,
* avoid broad rewrites that risk breaking what already works,
* use constraints strategically to control generation behavior,
* keep prompt modifications local to the problematic scene.

Prompt engineering changes made during iteration should be recorded in the scene prompt so the storybook remains reproducible.

Image Anchors
--------------

Image anchors are the concept reference artworks generated by the artwork-generation skill. They provide concrete visual references to the image generator alongside the textual prompt. Artworks are a **strict prerequisite**: illustrations cannot be generated until the reference artworks for referenced concepts exist on disk.

When generating an illustration for a scene:

* the prompt builder compiles an indexed `## Concepts` section matching the exact order of the attached reference images,
* the scene prompt retains the anchor tags as conceptual identifiers (e.g. `LEO is playing with his TOY_CAR`),
* anti-editing instructions instruct the model to compose a brand-new illustration from scratch rather than modifying the reference artworks,
* the client delivers the reference artwork images corresponding to those concepts in matching order.

The mechanism for passing image anchors to the generation API depends on the provider (e.g., multimodal image parts in Gemini, logged warning in ComfyUI checkpoint workflow).

Generation Constraints
----------------------

The repository provides default generation constraints. Custom constraints may be defined in the storybook when needed.

During iteration:

* prefer adjusting the scene prompt before adding scene-specific constraints,
* use constraints to enforce hard rules (e.g., no text, single scene) rather than aesthetic preferences,
* avoid accumulating constraints that duplicate what the prompt already expresses.

Output Validation Rules
-----------------------

Before declaring illustration generation complete, verify through repository tools and validators that:

* the canonical storybook artifact respects the repository schema,
* every scene has an illustration image at its recorded path,
* every illustrated book part has an illustration image at its recorded path,
* image paths are valid relative paths within the story workspace,
* the illustrations are visually consistent with the global style,
* recurring concepts are recognizable across scenes.

Completion
----------

The work is complete only when all illustrations are generated, reviewed, and structurally validated.

Quality is assessed collaboratively with the user. If the user is not satisfied with specific illustrations, iterate on those scenes using prompt engineering.

If a storage-management skill exists, use it for file placement and naming.
